# scripts/packaging

Builds the customer zips and judges them. Excluded from every shipped artifact
(`scripts/packaging/**` is on the `never_ship` list).

- `tiers.json` -- the tier declaration: the shared `ship` / `never_ship` lists
  plus the per-tier `exclude`, `forbidden_content`, and `config_pins`. The tiers
  are `enhanced` and `basic`.
- `build_zips.py` -- cuts a tier: `--tier enhanced|basic|all`. Each tier
  produces TWO artifacts (see below).
- `build_custom.py` -- cuts a per-client zip from a profile in `profiles/`,
  still honoring the profile's `zip_tier`. Always the without-tests cut.
- `assert_zip.py` -- the judge: re-opens a built zip and fails if it carries
  anything its tier forbids, or if it is not the cut it claims to be. Every
  build prints the assert command to run.

## Two cuts per tier

D4 (Rico, 2026-09-01): `tests/` is neither always shipped nor always withheld,
so every tier build writes both and Rico picks which one a customer receives.

| artifact | `tests/` | `TESTS-NOTE.md` |
| --- | --- | --- |
| `inbox-zero-connector-<tier>-<version>.zip` | no | no |
| `inbox-zero-connector-<tier>-<version>-with-tests.zip` | yes | yes |

`TESTS-NOTE.md` is GENERATED by the builder (it is not a file in the tree) and
states that the draft/voice strings under `tests/` are test fixtures, not
runtime behaviour -- the person who opens the zip is not the person who was
told.

The judge takes the cut as a flag and checks the bytes, never the filename:

```
uv run python scripts/packaging/assert_zip.py             dist/...-<version>.zip            enhanced
uv run python scripts/packaging/assert_zip.py --with-tests dist/...-<version>-with-tests.zip enhanced
```

Order matters in the build log: the with-tests cut is written FIRST, so the
LAST `BUILT` / `ASSERT WITH:` lines name the plain cut -- which is what
`scripts/kit-release` reads with `tail -1` when it decides what to land on the
share.
